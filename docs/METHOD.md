# 算法、优化与信息边界

## 最终 Bot

`champion` 从 `policies/champion.json` 加载冻结参数。它不是神经网络，不需要 GPU 或模型下载。舰船的几何约束和公开反馈足够支持直接推断，避免在有限资源下从零学习规则。

1. **候选布局筛选。** 每种剩余舰长预计算水平、竖直直线位置。排除包含落空或已击沉格的候选；排除已经全部命中却没有公开击沉的候选。只剩一艘时必须覆盖全部未归属命中。两个 3 格舰按两个独立舰计数。
2. **搜索。** 统计未知格被各候选覆盖的热度，用开发集选择的舰长权重和边缘修正调整取点。最终长度权重偏向更难找到的短舰，避免只提高早期命中率却拖长最后一艘的寻找时间。
3. **追击。** 有命中时，对完整剩余舰队做顺序重要性采样，要求舰船不重叠且覆盖全部命中。每次选择可覆盖一个确定命中的合法分支，乘上分支数作为逆提议概率；无法完成的样本权重为零。公开反馈只有命中、落空、击沉，不假定相邻命中一定属于同一艘船。
4. **稳定取点。** 有限采样会产生噪声。最终策略将联合推断得分与确定性的单舰追击得分各混合 50%，并奖励继续击中已经受损的舰船。不是单纯“选占舰概率最大的格子”。
5. **残局。** 联合候选组合不超过 20,000 时完整枚举；只剩一舰且候选不超过 6 个时，用 Bellman 递归计算击沉所需的期望剩余发数，比较命中与落空分支。状态超过 15,000 时放弃不完整搜索，退回常规策略。
6. **部署。** 每局新生成 12 套随机舰队，部署风格来自 uniform/edge/cluster/spread 混合。用 Hunt 和两次独立随机性的 Density 模拟攻击，按加权击沉发数排序，从最好的两套中随机选一套。不使用固定布局库或最终评估种子。

最终参数见 JSON，不依赖当前聊天状态。未经优化的 `admiral`、纯 `density`、`hunt`、`random` 都保留，便于公平对照。

## 概率的含义与近似

`uniform` 部署通过“独立抽取所有舰船，再整套拒绝重叠”生成，因此在合法的有标签舰队集合上均匀。通常的逐舰拒绝采样不具备这个性质，本项目没有把它称作均匀。

重要性采样针对均匀舰队先验下的当前公开约束。它是有限样本的自归一化估计，**不是精确概率**；精确枚举模式才对该先验精确。edge/cluster/spread 对手会造成先验失配；边缘修正和开发集混合风格优化只是减轻失配，不能保证应对任意部署分布。

Bellman 残局假设剩余候选等概率，最小化平均击沉发数。它不等价于针对某一对手当前剩余进度直接最大化胜率。配套消融如实报告它的实际效果。

另保留 `constraint` 和 `adaptive` 实验模式：枚举受损舰的归属，用未受损舰有效位置数乘积近似完成舰队的权重。这个近似忽略未受损舰之间的排斥，文档与诊断字段均标注为 `constraint_approx`，不是精确后验。最终是否使用它由开发验证选择。

## 训练与选择

所有优化是可重复参数搜索和部署自评估，没有在线 API、深度 RL 或未保存的模型权重。

| 阶段 | 开发 / 验证种子 | 内容 |
|---|---|---|
| 初版搜索 | 10000–10099 / 30000–30099 | 16 组采样、混合、目标权重参数 |
| 联合推断细化 | 11000–11149 / 31000–31299 | 21 组采样量与追击奖励 |
| 确定性约束试验 | 同上 | 8 组约束近似策略 |
| 搜索权重优化 | 12000–12199 / 32000–32499 | 48 组舰长、边缘、奇偶、追击参数 |
| 残局与部署 | 33000–33299 / 34000–34199 | 残局阈值、候选部署数量 |
| 最终选择 | 35000–35599 | 7 个组合，每个在四种风格共 2,400 个棋盘上验证 |
| 冻结后的主评估 | 900000–900499 | 新种子；交换先后手；统一部署与自主部署 |
| 冻结后的压力评估 | 910000–910199 | 新种子；edge/cluster/spread |
| 冻结后的攻击消融 | 920000–920499 | 同棋盘比较各组件 |
| 冻结后的部署消融 | 930000–930499 | 同攻击算法，比较有无部署优化 |

最后一轮按开发验证平均击沉发数选择，不读取最终测试结果。最终对局不用于重新调整参数。

初版代码开发过程中有新增参数和规则约束修复，早期探索日志保留供审计，不保证用最终源码逐条复现这些旧日志。`endgame-invalidated-before-fix.json` 明确作废：单舰候选未强制覆盖全部命中。修复后重新运行的结果为 `endgame.json`。冻结后的评估保存源码/策略哈希并提供完整复现入口。

## 信息隔离

环境隐藏状态仅在裁判与部署自模拟中使用。所有攻击入口只接收字典观察；没有把 `Game`、`Target`、棋盘种子或全状态回放交给 Bot。Bot 私有随机流与裁判棋盘随机流通过不同标签的 SHA-256 派生。

测试包含两套不同隐藏布局产生相同观察、观察副本修改不污染环境、概率与独立小棋盘穷举一致、真实 JSONL 子进程完成整局以及超时进程终止。进程协议证明可隔离接口，但不等同于防恶意程序的操作系统沙箱。

## 可复现性

相同源码、JSON 策略、种子和支持的 Python 版本会得到同样的动作与胜负。为了复现保存的成绩建议使用已测试的 Python 3.14.7；不同 Python 版本的随机算法实现变化可能改变个别轨迹。耗时随机器负载变化，不能保证逐毫秒复现。

每对种子重复两个先后手对局，它们共享舰队与 Bot 随机流，因此不是两个独立样本。报告按种子整组重采样置信区间，避免把交换先后手的重复当作样本翻倍。
